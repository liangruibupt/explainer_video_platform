# explainer_video_platform 设计文档

状态：草案，待评审。日期：2026-11-03。

## 1. 目标

把 [基础版 skill](../skills/explainer-video-pipeline/) 扩展成一个创作平台。用户用一句话、一段对话或一张工作流图，产出图像、视频、音乐，以及把三者拼起来的讲解视频。

进阶版要做到七件事：

1. 生图、生视频、生音乐，用自部署的开源模型。
2. 模型部署在云上 GPU，闲置时缩容到 0，有任务时自动启动。
3. 工作流编排：节点图描述一条生产线，后端按图执行。
4. Agent 根据一句话自动生成工作流。
5. 对话方式创作视频、图片、音乐。
6. 用户差评后，自动找原因并提出 skill 的改进，经人工批准后生效。
7. 基础版的代码绘制路线（Remotion / HTML / Manim）保留，作为工作流里的一种节点。

参考了 Muse Studio 的三个界面：工作台、模型部署、工作流编辑器（见第 9 节）。

### 不在范围内

- 多租户计费、付费墙。
- 自训练或微调模型。只做推理部署。
- 移动端。

## 2. 总体架构

```
浏览器（工作台 / 对话 / 工作流编辑器 / 作品集 / 设置）
        │  HTTPS + WebSocket（任务进度）
        ▼
API 服务（FastAPI）── 鉴权、项目、作品、任务、工作流 CRUD
        │
        ├── 编排器：把工作流图拆成任务，按依赖顺序派发，收集结果
        │       │
        │       ├── Agent 节点 ──▶ Bedrock（Claude Opus 5.5 等）
        │       ├── 代码绘制节点 ──▶ 渲染 Worker（CPU，Remotion/Playwright/Manim）
        │       ├── 图像节点 ────▶ SageMaker 异步端点：Qwen-Image 2.1
        │       ├── 视频节点 ────▶ SageMaker 异步端点：MiniMax H3
        │       ├── 音乐节点 ────▶ SageMaker 异步端点：YuE2-3B
        │       └── 配音/字幕 ──▶ Polly / Whisper（渲染 Worker 内）
        │
        ├── 任务队列：SQS（任务）+ DynamoDB（任务状态、工作流运行记录）
        └── 存储：S3（模型权重缓存、输入素材、产出作品）
```

设计原则：

- **GPU 只跑生成模型。** 编排、Agent 调用、代码绘制、配音、字幕都在 CPU 上，常驻成本低。
- **所有生成都是异步任务。** 前端提交后拿到任务 ID，通过 WebSocket 看进度。这样冷启动几分钟也不会让请求超时。
- **一个模型一个端点。** 用多少部署多少，和 Muse Studio 设置页一致。

## 3. 生成模型（阶段 2）

| 模块 | 模型 | 许可证 | 建议机型 | 说明 |
|---|---|---|---|---|
| 图像 | [Qwen-Image 2.1](https://huggingface.co/Qwen/Qwen-Image-2.1)（7B DiT，FP8） | Qwen Research License | ml.g7.2xlarge（RTX PRO 4500，32 GB） | 文生图、编辑、透明 PNG，最多 10 张参考图 |
| 视频 | [MiniMax H3](https://huggingface.co/MiniMaxAI/MiniMax-H3)（GGUF Q8） | MiniMax H3 Community License | ml.g7.4xlarge | 画面和同步音频一次生成；社区实测单张 24 GB 卡可跑 |
| 音乐 | [YuE2-3B](https://huggingface.co/m-a-p/YuE2-3B)（BF16） | CC BY-NC 4.0 | ml.g7.2xlarge | 歌词 + 风格 → 完整歌曲，48 kHz 立体声，附 ABC 乐谱 |

**许可证要先确认。** 三个模型都不是 Apache/MIT：

- Qwen Research License 和 CC BY-NC 4.0 限制商用。YuE2 作者另外允许个人创作者出售生成的歌曲，但模型本身仍是非商用许可。
- 如果平台要商用，需要逐个读许可证全文，或者换成可商用的替代模型。

每个模块都留一个 **演示模式**（返回预置样例，不调 GPU），用于前端开发和没有部署端点时的体验。

## 4. 云上 GPU 部署与缩容到 0（阶段 2）

### 方案：SageMaker 异步推理端点

AWS 文档明确支持异步端点缩容到 0 实例。缩到 0 期间收到的请求会排队，等实例起来后处理（[Autoscale an asynchronous endpoint](https://docs.aws.amazon.com/sagemaker/latest/dg/async-inference-autoscale.html)）。

每个端点配置三样东西：

1. **注册伸缩目标**：`MinCapacity=0`，`MaxCapacity=N`（每个模型单独设）。
2. **目标跟踪策略**：指标 `ApproximateBacklogSizePerInstance`，负责扩容和缩回 0。
3. **从 0 启动的步进策略**：CloudWatch 告警监控 `HasBacklogWithoutCapacity`（队列有任务但没有实例），触发后加 1 个实例。没有这条，从 0 启动要等队列长度超过目标值。

请求和结果都走 S3：输入写到 S3，调用 `InvokeEndpointAsync`，结果写回 S3 并通过 SNS 通知编排器。

### 冷启动

从 0 启动 = 拉起实例 + 拉镜像 + 加载权重。要缩短它：

- 权重提前放到同区域 S3（设置页的「模型缓存（S3）」），容器启动时从 S3 读，不从 Hugging Face 下载。
- 容器镜像只放运行时，不打包权重。

实际冷启动时间要在阶段 2 实测后写进本文档。前端要明确显示「正在启动 GPU（约 N 分钟）」，不能让用户以为卡死了。

### 成本估算

ml.g7.2xlarge 在部分区域的按需价格约 $3.15/小时（来源：[cloudprice.net](https://cloudprice.net/aws/sagemaker/instances/ml.g7.2xlarge)，2026-11-02 数据）。部署前用 AWS 价目表核对实际区域的价格。

| 场景 | 估算 |
|---|---|
| 一直开着 1 个 2xlarge 端点 | 约 $3.15 × 730 小时 ≈ $2,300/月 |
| 缩容到 0，每天实际使用 2 小时 | 约 $3.15 × 2 × 30 ≈ $190/月（另加冷启动时间） |
| 缩容到 0，没人用 | 端点实例费用 ≈ $0；S3 存权重、CloudWatch 告警有少量费用 |

缩容到 0 之后，闲置时省下的就是实例费。代价是每次第一个请求要等冷启动。

### 部署管理

设置页「模型部署」对应一组后端操作：部署、重新部署、删除端点、查看状态和部署日志、切换云端/演示模式。这些操作由 API 服务调用 boto3 完成，凭证用部署机器的 IAM 角色，不在代码或配置文件里存密钥。

## 5. 工作流编排（阶段 3）

### 工作流格式

一个工作流是一张有向无环图，存成 JSON：

```json
{
  "id": "wf_mv_from_one_line",
  "name": "一句话做 MV：歌曲 + 封面 + 视频",
  "nodes": [
    {"id": "n1", "type": "input.text", "params": {"text": ""}},
    {"id": "n2", "type": "agent.lyrics", "params": {"model": "claude-opus-5.5"}},
    {"id": "n3", "type": "music.yue2", "params": {"seconds": 60}},
    {"id": "n4", "type": "agent.image_prompt", "params": {}},
    {"id": "n5", "type": "image.qwen", "params": {"ratio": "16:9"}},
    {"id": "n6", "type": "video.h3", "params": {"seconds": 10}},
    {"id": "n7", "type": "review.human", "params": {}},
    {"id": "n8", "type": "output.save", "params": {}}
  ],
  "edges": [
    {"from": "n1.text", "to": "n2.theme"},
    {"from": "n2.lyrics", "to": "n3.lyrics"},
    {"from": "n1.text", "to": "n4.idea"},
    {"from": "n4.prompt", "to": "n5.prompt"},
    {"from": "n5.image", "to": "n6.first_frame"},
    {"from": "n3.audio", "to": "n6.audio"},
    {"from": "n6.video", "to": "n7.input"},
    {"from": "n7.output", "to": "n8.work"}
  ]
}
```

### 节点类型

和 Muse Studio 节点库的分组一致：

| 分组 | 节点 |
|---|---|
| 输入 | 文本、图片、音频、视频、参考资料（URL） |
| AI Agent | 写词、写分镜、写图像提示词、写视频提示词、联网检索 |
| 图像 | 生成、编辑、抠图（透明背景） |
| 视频 | 文/图生视频、代码绘制（Remotion / HTML / Manim，即基础版 skill） |
| 音乐 | 生成歌曲、生成纯音乐、合成垫乐（基础版） |
| 文本 | 拼接、模板、翻译 |
| 音频 | Polly 配音、Whisper 字幕、音效、混音 |
| 审核与质检 | 人工审核（暂停等待确认）、自动质检（时长、分辨率、响度、字幕可读性） |
| 输出 | 保存作品、导出 MP4、发布 |

每个节点类型声明输入端口、输出端口、参数 schema 和执行方式（CPU worker、GPU 端点或 Agent 调用）。编辑器和后端读同一份声明，节点库可以扩展。

### 执行

- 编排器做拓扑排序，没有依赖的节点并行执行。
- 每个节点的结果存到 S3，并按「节点类型 + 参数 + 输入哈希」做缓存键。改了下游节点重跑时，上游直接用缓存，不重新生成（GPU 生成贵，这点很重要）。
- **人工审核**节点让运行进入「等待审核」状态，用户在任务中心批准或打回后继续。
- **候选数**：一个节点可以生成多个候选（截图里的「候选 × 1」），审核时选一个往下走。
- 失败重试有上限；失败的节点可以单独重跑，不必重跑整张图。

## 6. Agent 生成工作流（阶段 3）

用户输入一句话，例如「先帮我查查资料，再做一条科普短视频」：

1. Agent 拿到节点库的声明（类型、端口、参数 schema），输出一份工作流 JSON。
2. 后端校验：图无环、端口类型匹配、必填参数都有、引用的模型已部署或可用演示模式。校验失败就把错误返回给 Agent 改，最多 3 轮。
3. 校验通过后在编辑器里打开，用户可以改，也可以直接运行。

工作流编辑器右侧的「AI 助手」用同一套机制：用户说「加一个人工审核节点在视频后面」，Agent 改图，前端显示差异，用户确认后生效。

常用工作流（一句话做 MV、15 秒产品宣传片、小红书封面、科普短视频）预置成模板，作为「快捷开始」的入口。

## 7. 对话创作（阶段 4）

工作台的输入框和「对话创作」页共用一个 Agent：

- Agent 先判断用户要图像、视频、音乐还是组合（工作台的 Agent / 图像 / 视频 / 音乐按钮可以手动指定）。
- 信息不够时一步步问（风格、时长、比例、有没有参考图），问够了就生成工作流并运行。
- 「允许联网检索资料」开关控制 Agent 能不能调用联网检索节点。
- 生成过程中在对话里显示进度和中间结果（歌词、封面图、分镜），用户可以在对话里说「封面换成夜景」，Agent 只重跑相关节点。

「引导创作」是同一个 Agent 的表单模式：按步骤填参数，适合不熟悉提示词的用户。

## 8. 差评驱动的 skill 自动改进（阶段 5）

### 流程

1. 作品页有「不满意」按钮，用户选原因（画面、声音、字幕、内容、节奏、其他）并可以写一句话。
2. 系统记录这条反馈和对应的工作流运行记录（每个节点的参数、输入、输出、质检结果）。
3. 分析 Agent 读反馈、运行记录和当前 skill 的规则，判断问题出在哪一层：
   - **某次生成的偶然失败**（例如这张图手指画错了）：直接用新种子或改提示词重跑那个节点，不改 skill。
   - **规则缺失或错误**（例如音乐总是盖过人声、某种场景总是超时长）：起草对 SKILL.md、脚本参数或节点默认值的修改。
4. 修改以 **PR 的形式**提交到本仓库，附上反馈原文、运行记录链接、改动理由。**人工批准合并后才生效。** 系统不会自动改动线上 skill。
5. 合并后，用同一个输入重跑一次，确认问题消失，把结果回复到原反馈下。

### 防止改坏

- 同一类问题累计出现多次（例如 3 次）才起草规则级修改，避免被单个偏好带偏。
- 每个规则修改都要附一个能复现问题的测试输入。PR 的检查里要跑这个输入，比较修改前后的质检指标。
- skill 有版本号；线上运行记录里写明用的是哪个版本，方便回滚和对比。

## 9. 界面（阶段 4）

参考 Muse Studio 的结构：

| 区域 | 页面 | 内容 |
|---|---|---|
| 创作 | 工作台 | 一个输入框 + Agent/图像/视频/音乐选择 + 联网开关 + 快捷开始 + 最近作品 |
| 创作 | 图像 / 视频 / 音乐 | 单一模态的生成页，参数完整 |
| 创作方式 | 对话创作、引导创作、工作流 | 见第 5–7 节 |
| 资产与管理 | 作品集、素材库、任务中心、项目 | 作品浏览、上传素材、任务进度与人工审核、按项目分组 |
| 设置 | AWS 与基础资源、模型部署、完成通知、模型缓存（S3）、外观、账号、用户管理 | 模型部署页每个模块一张卡片：状态（待命中 / 已缩到 0 / 运行中）、版本、机型、端点、重新部署、删除端点、部署日志、云端/演示切换 |

前端技术栈在阶段 4 开始前确定（倾向 React + 一个现成的节点图库，如 React Flow）。

## 10. 安全

- AWS 凭证只用 IAM 角色，最小权限：API 服务只能调用本平台的 SageMaker 端点和本平台的 S3 前缀。
- 用户上传的素材和生成结果按项目隔离存放，S3 链接用短期预签名 URL。
- Agent 节点读到的网页内容按数据处理，不当作指令执行。
- 删除端点、删除作品等操作需要二次确认。

## 11. 阶段与验收标准

| 阶段 | 内容 | 验收 |
|---|---|---|
| 1 基础版 | 本仓库的 `skills/explainer-video-pipeline` | 已完成：Canvas 和 Manim 两条路线端到端出片，时长、音效、字幕实测对齐 |
| 2 云端生成 | 图像、视频、音乐三个 SageMaker 异步端点，缩容到 0；部署/删除/状态脚本；S3 权重缓存 | 每个模块：从 0 冷启动出一个结果并记录耗时；闲置 N 分钟后实例数回到 0；成本按实测更新第 4 节 |
| 3 工作流 | 工作流 JSON 格式、节点声明、编排器、缓存、人工审核；Agent 生成工作流 | 「一句话做 MV」模板能端到端跑通；改一个下游参数重跑时上游命中缓存；Agent 对 5 个不同句子生成的工作流全部通过校验并能运行 |
| 4 界面 | 工作台、对话创作、工作流编辑器、作品集、任务中心、设置 | 不写代码就能完成：对话出一张图、模板出一支 MV、在编辑器里改图并重跑 |
| 5 自我改进 | 差评收集、分析 Agent、PR 起草、复现测试 | 人为制造一个已知问题（例如音乐过响），提交差评后系统起草出正确的修改 PR，合并后重跑问题消失 |

阶段 2 先做图像模块，跑通部署和缩容到 0 的整条链路，再复制到视频和音乐。
